# Тренажёр теста «Электрические сети» — Telegram Mini App

Веб-приложение для тренировки теста по дисциплине «Электроэнергетические системы и сети».
**398 вопросов, 24 раздела.** Правильные ответы взяты из отметок в учебнике.

## Что внутри
- `index.html`, `styles.css`, `app.js` — само приложение (статика, без сервера).
- `questions.json` — база вопросов.
- `images/` — схемы (рис. 1.1, 5.1 …). Пока пустая: вопросы со схемами показывают подпись «см. рисунок в учебнике», пока картинки не добавлены.
- `ПРОВЕРИТЬ_ОТВЕТЫ.md` — список из 32 вопросов, где отметка в книге была спорной/отсутствовала. Стоит сверить.

## Режимы
Весь тест · Случайные 25 · Работа над ошибками · Спорные вопросы · по разделам. Прогресс сохраняется в браузере.

## Как запустить локально
```bash
python3 -m http.server 4137
```
Открыть http://localhost:4137

## Публикация на GitHub Pages (бесплатно)
1. Создайте репозиторий на github.com (например `seti-test`), **Public**.
2. Загрузите в него все файлы из этой папки (можно через сайт: *Add file → Upload files*).
3. В репозитории: **Settings → Pages → Source: Deploy from a branch → Branch: `main`, папка `/root` → Save**.
4. Через 1–2 минуты появится адрес вида `https://<ваш-логин>.github.io/seti-test/`. Это HTTPS-ссылка — она нужна для Telegram.

## Подключение к Telegram (BotFather)
1. В Telegram напишите **@BotFather** → `/newbot` → задайте имя и username бота → получите **токен** (храните его в секрете).
2. `/newapp` → выберите бота → заполните название/описание/иконку → на шаге **Web App URL** вставьте ссылку с GitHub Pages (из шага выше).
3. BotFather выдаст ссылку вида `https://t.me/<bot>/<app>` — по ней открывается Mini App.
4. (Опционально) `/setmenubutton` → выбрать бота → вставить тот же URL → кнопка-меню в чате будет открывать тренажёр.

Готово — открываете Mini App в Telegram и тренируетесь.

## Обновление вопросов
Отредактируйте `questions.json` и перезалейте на GitHub — приложение подхватит изменения. Формат записи:
```json
{"id":1,"section":1,"section_title":"…","n":1,"q":"текст вопроса",
 "options":["вариант A","вариант B"],"correct":[0],"figure":"fig_1_1","uncertain":false}
```
`correct` — массив индексов правильных вариантов (0 = первый). Несколько индексов = вопрос с несколькими ответами.
`figure` — имя файла в `images/` без расширения (необязательно). `uncertain:true` — помечает вопрос значком ⚠.

## Модуль «Расчёт режима»

Расчётный движок, пошаговый разбор, банк тестов на понимание формул и **диагностика ошибок по числовому ответу**. Цель — не «неверно», а «вы забыли разделить R_л на число цепей — ваш ответ ровно вдвое больше верного».

### Команды
```bash
npm install          # один раз (только ajv для проверки схем; на деплой не влияет)
npm test             # 110 юнит-тестов (node --test): формулы, решатель, эталон, диагностика, генератор, банк, схемы
npm run build:quiz   # пересобрать content/formula-quiz/*.json из content-src/formula-quiz.mjs
npm run compare      # таблица сходимости движка рядом с эталоном
```

### Структура
```
calc/                чистые функции (без DOM и сети), покрыты тестами
  params.js          x0, b0, R/X/B линии, R_T, X_T, потери х.х.   (единицы: МВт, Мвар, кВ, Ом, См)
  regime.js          dS, Qc, dU, deltaU, модуль напряжения, U_нн
  network.js         модель «узлы + ветви», сборка сети из варианта (тип A и тип B — одна модель)
  solver.js          solveRegime: «мощности вперёд — напряжения назад», полный журнал итераций
  steps.js           пошаговый разбор из журнала решателя (формула, подстановка, результат, типовая ошибка)
  misconceptions.js  РЕЕСТР ошибок студента — единый источник для дистракторов, диагностики и подсказок
  quantities.js      реестр проверяемых величин (единицы, допуски)
  diagnose.js        diagnose(величина, число студента, вариант) → диагноз
  variants.js        generateVariant(seed, {type:'A'|'B'}) + sanity-check
  quiz-bank.js       проверка ответов, статистика ошибок, «слабые места», тренировка по ключам
  quiz-build.js      сборка банка: плейсхолдеры {{ref:…}} → числа из движка
fixtures/km2_reference.json   эталон (ВЛ 220 кВ + 2×ТРДН-40000/220): единственное место с числами эталона
content-src/formula-quiz.mjs  ИСХОДНИК банка (58 вопросов, 3 теста, 7 типов)
content/formula-quiz/         собранный банк (JSON) + content/schema/ (JSON Schema)
formula-quiz.js               UI модуля (экран «Расчёт режима» на главной)
```

### Как это устроено
* **Ошибки живут рядом с правильной формулой.** Каждая функция принимает `faults` (`{missing_U_square:true}` и т.п.) и в этом случае считает так, как ошибается студент. Дистракторы теста и «отпечатки» для диагностики берутся из одного места и не могут разъехаться.
* **Диагностика** пересчитывает шаг с каждой из 24 числовых ошибок и сравнивает с ответом студента (допуск ±2 %, для напряжений — абсолютный ±0.15 кВ). Ошибка своего шага приоритетнее той, что «протекла» из предыдущих; неоднозначные случаи честно помечаются.
* **Числа в тестах не пишутся руками:** в тексте `{{ref:R_T|2}}`, `{{fault:missing_U_square:dS_line_P|1}}`, `{{in:transformer.Uvn}}` — их подставляет `npm run build:quiz` из движка. Тест `content` падает, если собранный JSON устарел.
* **Фидбэк неверного варианта** по умолчанию берётся из реестра ошибок; там, где формулировка варианта требует другого объяснения, есть переопределение в `OVERRIDES` (52 штуки).

### Как добавить
* **Новую ошибку:** запись в `calc/misconceptions.js` + флаг `faults.<key>` в нужной формуле + зонд (`probe`). Тесты сами проверят, что она отличима и диагностируется.
* **Новый вопрос:** запись в `content-src/formula-quiz.mjs` → `npm run build:quiz` → `npm test`.

### Допущения (сверьте со своим справочником)
* Паспортные данные ТРДН-25000/63000 и проводов АС 240/400 в `calc/variants.js` — типовые справочные значения, а не данные вашего учебника.
* Допуск ±1 % для эталонной таблицы применяется с «порогом половины последнего разряда» (эталон округлён до 0.01, а для 0.19 МВт 1 % — это 0.002).
* После обновления `calc/*.js` пользователям Telegram может понадобиться обновить страницу (браузер кэширует модули); версии `?v=` в `index.html` поднимайте при каждом деплое.

## Второй тест (КМ-2)

На главной вверху переключатель **КМ-1 / КМ-2**. У каждого набора свои разделы, режимы и **отдельный прогресс** (в браузере хранится под разными ключами). Модуль «Расчёт режима» общий.

* **Источник КМ-2:** `Test2.pdf` (текстовый PDF «КМ-2_осень_2023»; правильные ответы — зелёные галочки слева от варианта). В репозиторий сам PDF не входит (`.gitignore`).
* **Данные:** `questions_km2.json` (412 вопросов, разделы по 30) и `images/km2/` (93 рисунка + 8 вариантов-формул).
* **Пересборка из PDF:** `python3 scripts/extract_km2.py` (нужны `pip install pymupdf pillow pymorphy3 pymorphy3-dicts-ru`). Скрипт заново создаёт `questions_km2.json`, `images/km2/*` и `ПРОВЕРИТЬ_КМ2.md`.
* **Что делает скрипт:** привязывает каждую галочку к ближайшей строке/картинке; склеивает «ряды» (индексы, скобки); пишет индексы как `_{нб}` и `^{3}` (приложение рисует их); расклеивает слова, слипшиеся в исходнике (`верныйзнак → верный знак`), по словарю pymorphy3; склейка длинных вариантов, разрезанных в исходнике, задана явным списком `MERGE` (решения приняты просмотром каждого стыка).
* **Не вошло (10 вопросов):** в файле нет правильного ответа (№5, 61, 77, 78), задания на соответствие (№253, 254) и упорядочивание (№387–390). Список — в `ПРОВЕРИТЬ_КМ2.md`; пришлите ключ, и их можно добавить.
* **С пометкой ⚠ (11 вопросов):** в самом PDF потеряна часть формулы или знаков (например, интервалы «0 … 1» остались как «0», «1»). Ответ взят из галочки, но условие неполное.
* Водяной знак «123xyz.ru» вшит в картинки исходного сайта; он не удалялся.
